# Pydantic Schema Design Skill

## Name
Pydantic v2 Request/Response Schema Design

## Description
This skill provides comprehensive guidance for creating production-ready Pydantic v2 schemas for request validation and response serialization in the NutriChef AI platform. It covers schema design patterns, validation rules, field configuration, and integration with FastAPI and Beanie ODM.

## Purpose
To ensure consistent, type-safe, and well-validated API contracts using Pydantic v2, following Clean Architecture principles and NutriChef AI coding standards.

## When to Use
- Creating request schemas for API endpoints (Create, Update operations)
- Creating response schemas for API responses
- Defining validation rules for user input
- Implementing custom validators for business logic
- Converting between Beanie models and API schemas
- Refactoring existing schemas to Pydantic v2
- Implementing partial update schemas (PATCH operations)

## Inputs
- **Resource Name**: The entity being modeled (e.g., Recipe, User, MealPlan)
- **Operation Type**: Create, Update, Patch, or Response
- **Field Definitions**: Field names, types, constraints, defaults
- **Validation Rules**: Business rules for field validation
- **Beanie Model**: Corresponding database model (if applicable)
- **Relationships**: References to other schemas

## Outputs
- **Schema File**: `backend/app/schemas/{resource}.py` with Pydantic models
- **Type-Hinted Fields**: All fields with proper Python 3.11 type hints
- **Validation**: Field validators and model validators
- **Documentation**: Field descriptions and examples
- **Config**: Pydantic model configuration (ConfigDict)
- **Separate Schemas**: Create, Update, Patch, and Response schemas

## Best Practices

### 1. Schema Naming Convention
- **Create**: `{Resource}Create` (e.g., `RecipeCreate`)
- **Update**: `{Resource}Update` (e.g., `RecipeUpdate`)
- **Patch**: `{Resource}Patch` (e.g., `RecipePatch`) - all fields optional
- **Response**: `{Resource}Response` (e.g., `RecipeResponse`)
- **Base**: `{Resource}Base` (shared fields across schemas)

### 2. Field Configuration
- Use `Field()` for field metadata (description, examples, constraints)
- Use `...` (Ellipsis) for required fields
- Use `None` or default values for optional fields
- Add `description` for API documentation
- Add `examples` for OpenAPI docs

### 3. Validation
- Use `Field()` constraints for basic validation (min_length, max_length, gt, lt, ge, le)
- Use `@field_validator` for custom field validation
- Use `@model_validator` for cross-field validation
- Provide clear, actionable error messages
- Validate business rules, not just data types

### 4. Pydantic v2 Configuration
- Use `ConfigDict` instead of nested `Config` class
- Set `from_attributes=True` for ORM mode (Beanie models)
- Set `populate_by_name=True` for field aliases
- Set `str_strip_whitespace=True` to auto-trim strings

### 5. Schema Inheritance
- Create a base schema with shared fields
- Inherit from base for Create, Update, Response schemas
- Use composition over deep inheritance

### 6. Optional vs Required Fields
- Create schemas: Required fields only (no ID, timestamps)
- Update schemas: All fields required (full replacement)
- Patch schemas: All fields optional (partial update)
- Response schemas: All fields present (including ID, timestamps)

### 7. Type Safety
- Use strict type hints: `str`, `int`, `List[str]`, `Optional[str]`
- Use `datetime` for timestamps
- Use `EmailStr` for email validation
- Use `HttpUrl` for URL validation
- Use `constr`, `conint` for constrained types (Pydantic v2)

## Common Mistakes

### ❌ Mistake 1: Using Old Pydantic v1 Config Syntax
```python
# BAD: Pydantic v1 syntax
class RecipeResponse(BaseModel):
    class Config:
        orm_mode = True  # v1 syntax
```
**Fix**: Use Pydantic v2 ConfigDict
```python
# GOOD: Pydantic v2 syntax
from pydantic import BaseModel, ConfigDict

class RecipeResponse(BaseModel):
    model_config = ConfigDict(from_attributes=True)
```

### ❌ Mistake 2: Missing Type Hints
```python
# BAD: No type hints
class RecipeCreate(BaseModel):
    title = Field(...)
    ingredients = Field(...)
```
**Fix**: Add explicit type hints
```python
# GOOD: Full type hints
from typing import List

class RecipeCreate(BaseModel):
    title: str = Field(..., min_length=1, max_length=200)
    ingredients: List[str] = Field(..., min_items=1)
```

### ❌ Mistake 3: Including ID in Create Schemas
```python
# BAD: ID in create schema (generated by database)
class RecipeCreate(BaseModel):
    id: str  # Should not be in create schema!
    title: str
```
**Fix**: Exclude ID from create schemas
```python
# GOOD: No ID in create schema
class RecipeCreate(BaseModel):
    title: str = Field(..., min_length=1, max_length=200)
    ingredients: List[str] = Field(..., min_items=1)

# ID only in response schema
class RecipeResponse(BaseModel):
    id: str
    title: str
    ingredients: List[str]
```

### ❌ Mistake 4: Not Using Field Descriptions
```python
# BAD: No descriptions for API docs
class RecipeCreate(BaseModel):
    prep_time: int = Field(..., gt=0)
```
**Fix**: Add descriptions and examples
```python
# GOOD: Descriptions and examples for docs
class RecipeCreate(BaseModel):
    prep_time: int = Field(
        ...,
        gt=0,
        description="Preparation time in minutes",
        examples=[30, 45, 60]
    )
```

### ❌ Mistake 5: Weak Validation
```python
# BAD: No validation for empty strings
class RecipeCreate(BaseModel):
    title: str
```
**Fix**: Add proper validation
```python
# GOOD: Validate non-empty strings
from pydantic import field_validator

class RecipeCreate(BaseModel):
    title: str = Field(..., min_length=1, max_length=200)
    
    @field_validator('title')
    @classmethod
    def title_must_not_be_empty(cls, v: str) -> str:
        if not v.strip():
            raise ValueError('Title cannot be empty or whitespace')
        return v.strip()
```

## Examples

### Example 1: Complete Schema Set for Recipe

```python
# backend/app/schemas/recipe.py
from typing import List, Optional
from datetime import datetime
from pydantic import BaseModel, Field, ConfigDict, field_validator

class RecipeBase(BaseModel):
    """Base schema with shared fields."""
    title: str = Field(
        ...,
        min_length=1,
        max_length=200,
        description="Recipe title",
        examples=["Chicken Alfredo", "Vegan Buddha Bowl"]
    )
    description: Optional[str] = Field(
        None,
        max_length=1000,
        description="Recipe description"
    )
    ingredients: List[str] = Field(
        ...,
        min_items=1,
        description="List of ingredients",
        examples=[["chicken", "pasta", "cream"]]
    )
    instructions: str = Field(
        ...,
        min_length=10,
        description="Cooking instructions"
    )
    prep_time: int = Field(
        ...,
        gt=0,
        description="Preparation time in minutes",
        examples=[30]
    )
    cook_time: int = Field(
        ...,
        gt=0,
        description="Cooking time in minutes",
        examples=[45]
    )
    servings: int = Field(
        ...,
        gt=0,
        description="Number of servings",
        examples=[4]
    )

class RecipeCreate(RecipeBase):
    """Schema for creating a new recipe."""
    
    @field_validator('title')
    @classmethod
    def title_must_not_be_empty(cls, v: str) -> str:
        """Validate title is not empty or whitespace."""
        if not v.strip():
            raise ValueError('Title cannot be empty or whitespace')
        return v.strip()
    
    @field_validator('ingredients')
    @classmethod
    def ingredients_must_not_be_empty(cls, v: List[str]) -> List[str]:
        """Validate ingredients are not empty strings."""
        cleaned = [ing.strip() for ing in v if ing.strip()]
        if not cleaned:
            raise ValueError('At least one valid ingredient is required')
        return cleaned

class RecipeUpdate(RecipeBase):
    """Schema for full recipe update (PUT)."""
    pass

class RecipePatch(BaseModel):
    """Schema for partial recipe update (PATCH)."""
    title: Optional[str] = Field(None, min_length=1, max_length=200)
    description: Optional[str] = Field(None, max_length=1000)
    ingredients: Optional[List[str]] = Field(None, min_items=1)
    instructions: Optional[str] = Field(None, min_length=10)
    prep_time: Optional[int] = Field(None, gt=0)
    cook_time: Optional[int] = Field(None, gt=0)
    servings: Optional[int] = Field(None, gt=0)

class RecipeResponse(RecipeBase):
    """Schema for recipe responses."""
    model_config = ConfigDict(from_attributes=True)
    
    id: str = Field(..., description="Recipe unique identifier")
    author_id: str = Field(..., description="Recipe author user ID")
    created_at: datetime = Field(..., description="Creation timestamp")
    updated_at: datetime = Field(..., description="Last update timestamp")
```

### Example 2: Schema with Cross-Field Validation

```python
# backend/app/schemas/meal_plan.py
from datetime import datetime
from typing import List
from pydantic import BaseModel, Field, model_validator

class MealPlanCreate(BaseModel):
    """Schema for creating a meal plan."""
    name: str = Field(..., min_length=1, max_length=100)
    start_date: datetime = Field(..., description="Meal plan start date")
    end_date: datetime = Field(..., description="Meal plan end date")
    
    @model_validator(mode='after')
    def validate_date_range(self) -> 'MealPlanCreate':
        """Validate end_date is after start_date."""
        if self.end_date <= self.start_date:
            raise ValueError('end_date must be after start_date')
        return self
```

### Example 3: Schema with Custom Validators

```python
# backend/app/schemas/user.py
from pydantic import BaseModel, Field, EmailStr, field_validator
import re

class UserCreate(BaseModel):
    """Schema for user registration."""
    username: str = Field(
        ...,
        min_length=3,
        max_length=50,
        description="Unique username"
    )
    email: EmailStr = Field(..., description="User email address")
    password: str = Field(
        ...,
        min_length=8,
        description="User password (min 8 characters)"
    )
    
    @field_validator('username')
    @classmethod
    def username_alphanumeric(cls, v: str) -> str:
        """Validate username contains only alphanumeric characters and underscores."""
        if not re.match(r'^[a-zA-Z0-9_]+$', v):
            raise ValueError(
                'Username must contain only letters, numbers, and underscores'
            )
        return v.lower()
    
    @field_validator('password')
    @classmethod
    def password_strength(cls, v: str) -> str:
        """Validate password contains at least one uppercase, lowercase, and digit."""
        if not re.search(r'[A-Z]', v):
            raise ValueError('Password must contain at least one uppercase letter')
        if not re.search(r'[a-z]', v):
            raise ValueError('Password must contain at least one lowercase letter')
        if not re.search(r'\d', v):
            raise ValueError('Password must contain at least one digit')
        return v
```

### Example 4: Schema with Nested Models

```python
# backend/app/schemas/meal_plan.py
from pydantic import BaseModel, Field
from typing import List
from datetime import datetime

class MealEntryCreate(BaseModel):
    """Schema for a single meal entry."""
    recipe_id: str = Field(..., description="Recipe ID")
    meal_type: str = Field(
        ...,
        pattern="^(breakfast|lunch|dinner|snack)$",
        description="Type of meal"
    )
    date: datetime = Field(..., description="Meal date")
    servings: int = Field(..., gt=0, description="Number of servings")

class MealPlanCreate(BaseModel):
    """Schema for creating a meal plan with meals."""
    name: str = Field(..., min_length=1, max_length=100)
    start_date: datetime
    end_date: datetime
    meals: List[MealEntryCreate] = Field(
        default_factory=list,
        description="List of meals in the plan"
    )
```

### Example 5: Response Schema with Computed Fields

```python
# backend/app/schemas/recipe.py
from pydantic import BaseModel, Field, computed_field, ConfigDict
from typing import List
from datetime import datetime

class RecipeResponse(BaseModel):
    """Schema for recipe responses with computed fields."""
    model_config = ConfigDict(from_attributes=True)
    
    id: str
    title: str
    ingredients: List[str]
    prep_time: int
    cook_time: int
    servings: int
    created_at: datetime
    
    @computed_field
    @property
    def total_time(self) -> int:
        """Compute total time (prep + cook)."""
        return self.prep_time + self.cook_time
    
    @computed_field
    @property
    def ingredient_count(self) -> int:
        """Compute number of ingredients."""
        return len(self.ingredients)
```
